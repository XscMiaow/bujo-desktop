# 插件教程：自定义子弹

应用支持用**插件文件夹**扩展新的子弹类型（自定义符号），无需改任何代码。
放好插件 → 重启应用 → 子弹出现在图例、统计、按钮与解析器里。

## 一、文件夹从哪来、放哪里

插件统一放在项目根目录的 **`plugins/`** 文件夹：

```text
bujo-desktop/                     ← 项目根
  plugins/
    example-progress/             ← 每个子文件夹 = 一个插件（官方示例，可直接复制改）
      plugin.json                 ← 插件清单
    my-reading/                   ← 你自己的第二个插件
      plugin.json
```

- 文件夹名随意（建议英文 + 连字符），插件真正认的是清单里的 `id`。
- 文件夹里没有 `plugin.json` → 不当插件，静默忽略。
- 清单 JSON 写坏了 / 字段非法 → 不加载，主进程会记录一条错误（不弹窗、不影响其它插件）。

## 二、清单 plugin.json 字段逐个讲

```json
{
  "id": "my-reading",
  "name": "阅读集",
  "description": "把读书里的「在读/读完」做成自己的子弹",
  "bullets": [
    {
      "kind": "reading",
      "marks": ["r", "-r"],
      "native": ["📖"],
      "glyph": "📖",
      "label": "阅读",
      "cls": "is-reading",
      "color": "#7ac74f",
      "taskLike": true,
      "symbol": "📖 text"
    }
  ]
}
```

### 顶层字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 插件唯一 id：小写字母/数字/连字符，1-32 位 |
| `name` | 建议 | 显示名（自由文本，最多 40 字） |
| `description` | 否 | 一句话说明（最多 200 字） |
| `bullets` | 是 | 自定义子弹数组，至少一条有效 |

### 每条子弹（bullets 数组里的对象）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `kind` | 是 | 类型 id：`^[a-z][a-z0-9-]{0,23}$`。**不能与内置八类、`total`、`progress`、已注册的重复** |
| `marks` | 二选一 | 复选框写法：`["r"]` 支持 `- [r] 文字`；`!` 优先修饰符自动兼容（`- [r!]` = 阅读且优先） |
| `native` | 二选一 | 原生符号写法：`["📖"]` 支持 `📖 文字`（单字、非字母数字、不能占用 `o` / `•` / `·` / `○`） |
| `glyph` | 建议 | 图例里的显示符号（最多 3 字符；缺省用 native 第一项或 marks 第一项） |
| `label` | 建议 | 图例与统计里的名字（最多 20 字；缺省用 kind） |
| `cls` | 否 | 样式类名（缺省 `is-<kind>`；可以在 styles/ 里自己加样式） |
| `color` | 否 | 图例/符号颜色的 16 进制（原生写进 `--kind-<kind>` CSS 变量） |
| `taskLike` | 否 | 能否「完成」（默认 true；false 就只有划去/星标按钮） |
| `symbol` | 否 | 图例里展示的写法示例（缺省按下 marks/native 推导） |

`marks` 与 `native` 至少要有一种，两种都写也行（一套类型、两种写法）。

## 三、写完之后怎么用

1. 把**别人发你的插件文件夹**整个放进 `plugins/`（或自己按上一节新建）。
2. 重启应用（插件只在启动时扫描一次）。
3. 界面底部图例会出现新类型；顶部的统计条在笔记里有这类子弹时会显示数量胶囊。
4. 在任意日记里写一行：
   - `- [r] 看第 3 章`（marks 写法）
   - `📖 看第 3 章`（native 写法）
   效果：<span>📖</span> 符号 + 你设置的颜色。

手工操作与其它类型一致：

- 能「完成」（taskLike 默认 true）→ 变成 `- [x]` 同款划线样式。
- 能「划去」「加优先（★）」「取消完成」。
- 「迁移/推迟（»）」**不提供给自定义类型**——迁移语义要求知道目标日志的小节语义，自定义类型先不支持。

## 四、限制与已知行为

- **取消后恢复**：自定义类型被「划去」后，恢复回到**待办** `- [ ]`（不发原类型提示，因为那需要文件里携带额外信息；内置的笔记/事件才有恢复原类型的写法）。
- **并发与去重**：AI 写入、划去完成、迁移等一切写口照旧走同一套队列与锁，插件类型不会绕过它们。
- **清单里 marks 撞到内置标记**（如 `" "`、`x`、`>`）或撞到别的插件 → 这条子弹整个被拒（先到先得），不会覆盖内置行为。
- **id 冲突**：两个插件都用 `reading` → 后注册的那条失效（启动顺序按文件夹名字典序）。

## 五、常见问题

**Q：能改内置八类的符号/颜色吗？**
不能。插件只注册**新的**类型；内置类型的行为由应用本体维护。

**Q：插件能执行 JavaScript 吗？**
不能。清单是纯声明式的——只描述「这是什么符号、什么颜色」，不运行任何插件代码，这样插件永远改不了写入口与权限。

**Q：清单写坏了怎么排查？**
重启后打开设置正常界面无变化。检查 JSON 语法（少逗号/引号）、`kind` 是否合法、`marks` 是否撞车。
