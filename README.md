# 子弹笔记 · Bullet Journal Desktop

基于 Electron 的子弹笔记（Bullet Journal）桌面应用。

当前进度：**主窗口 + 左侧日记栏 + 读取并显示 .md 笔记 + 鼠标完成/划去/迁移推迟条目（[>] 迁到下月/未来、[<] 推到明天） + AI 聊天读写笔记（读已有笔记作上下文、可改已有条目、写入时整合去重） + 悬浮小窗（当天要点 + 精简聊天）**。
在窗口里直接输入新条目、拖拽排序是下一步，数据格式已经按子弹笔记语法打好基础（见下文）。

## 运行

```bash
npm install
npm start          # 启动应用
npm test           # 单元测试（解析器 + 文件读取 + 日记目录扫描 + 写入队列与 CLI）

# 端到端自检：preload → IPC → 解析 → 渲染 → 日记栏双击切换 → 折叠，并输出截图
npm run smoke
npm run smoke -- journals/2026/2026-10/2026-10-07.md   # 也可以指定自检打开的文件
```

也可以直接把 `.md` 文件拖进窗口，或用 `npm start -- journals/2026/2026-10/2026-10-07.md` 启动时直接打开。

## AI 聊天（与笔记打通）

右侧面板可以和模型聊天，**回答分成三段**：对话、要新增的条目、对已有条目的改动——
只有后两段会动到笔记：

- 点工具栏的「AI 聊天」（或 `Ctrl/Cmd + J`）展开右侧面板，聊天内容流式显示。
- 模型按协议用 `<chat>…</chat>`、`<journal>…</journal>`、`<note-edit>…</note-edit>` 分段
  （协议由应用自动追加到系统提示词里，也可以用小标题 `【日记】`、`日记块：`、`## 日记`、`笔记改动：` 代替标签）。
- **气泡里只显示对话**：解释、建议、追问都留在这里；**笔记草稿**单独成一张卡片，
  卡片下方才是「写入笔记」按钮——只有卡片里的内容会落盘，聊天里的寒暄不会被当成笔记条目。
- **参考笔记**（底部的「参考」下拉）：选「当前笔记」或「今天的日记」后，应用会把那一篇的现有内容
  作为 `<note file="…">…</note>` 附在你的提问后面发给模型（太长时首尾保留、中间省略，默认最多 2400 字）。
  这样 AI 能看到哪些事已经记过；选「不附带」就是纯粹聊天。
- **改动已有条目**：卡片上的「改动」清单来自 `<note-edit>`，一行一条——
  `改：原文 => 新写法`、`完成：原文`、`划去：原文`。应用按归一化后的文本在本篇笔记里模糊匹配（完全相同 → 内容近似），
  匹配不到就明确报「没找到」，宁可不改也不拿相近的行乱改。
- **不会有哪一行被默默删掉**：`删：` / `删除：` / `移除：` 这些写法也一律按「划去」处理（标记改成 `[-]`，原文留着），
  整篇笔记只会被改标记、改文字、追加新条目，行只增不减。
- **整合而非重复**：写入前会跳过与已有条目重复的新增条目（完全相同或高度相似），
  同一件事只是状态变了（待办 → 已完成等）就**就地改状态**，不再新增一条；
  一批新增里自己重复的也只留一条。卡片上会提前显示「对照当前笔记：新增 N 条 · 改动 M 处 · 跳过重复 K 条」。
- 写入时把内容改写成子弹笔记条目：`- [ ]` 之类的任务原样保留，`*` / `1.` / `>` 等写法统一成 `-`,
  代码块和标题原样保留；有新增条目时前面加一行 `**AI 记录 · 14:32**`（只有改动时不加时间戳），
  卡片上的「带提问」勾选后还会附上你的问题。写入结果会写明新增/并入/改动/跳过重复各几条。
- 按「记入」选择的目标，写进**当前打开的笔记**或**今天的日记**
  （今天的日志不存在时会按模板新建 `journals/2026/2026-10/2026-10-13.md` 这样的 年/月 路径）。
- 两段都为空时（AI 认为这轮没什么值得记的）不会写；模型完全不按协议回答时，
  卡片会说明白，并给一个「写入全文要点」的兜底按钮，不会默默把整段对话当笔记写进去。
- AI 回复前先显示等待态：气泡「正在思考…」+ 草稿卡「等待 AI 回复…」，
  收到流式增量后立即被真实内容替换，不会提前跳出空的「没有要写入」卡片。
- 生成过程中可以「停止」；没配密钥时会直接提示去设置。
- 真正的落盘在主进程完成：它重新读一遍文件、按同一套规则再算一次，
  渲染层只负责预览与展示（两边共用 [note-edit.js](src/shared/note-edit.js)，界面上的数字与文件里的结果一致）。

## 其它 agent 入口：bujo CLI

其他 agent / 脚本不需要打开窗口，可以通过 CLI 操作笔记文档，与应用共用同一套写入规则（子弹语法、去重、单行改标记）和同一套「有界串行写入队列」：

```bash
npm run cli -- read   journals/2026/2026-10/2026-10-10.md            # 输出笔记原文
npm run cli -- read   journals/2026/2026-10/2026-10-10.md --json     # 机器可读：{ ok, path, name, content }
npm run cli -- append journals/2026/2026-10/2026-10-10.md "- [ ] 新的待办"          # 追加一条条目
npm run cli -- append 新文件.md "- 第一条" --create --initial "# 新日记"  # 新建文件
npm run cli -- mark   journals/2026/2026-10/2026-10-10.md "写周报" --mark done      # 标记完成
npm run cli -- mark   journals/2026/2026-10/2026-10-10.md "不想做了" --mark cancelled  # 划去（原文保留，不真删）
npm run cli -- mark   journals/2026/2026-10/2026-10-10.md "写周报" --mark task      # 恢复为待办
npm run cli -- move   journals/2026/2026-10/2026-10-10.md "买牛奶" --to tomorrow       # 推迟到明天的日记（源行标 [<]）
npm run cli -- move   journals/2026/2026-10/2026-10-10.md "写周报" --to next-month     # 迁到下个月记录（源行标 [>]）
npm run cli -- move   journals/2026/2026-10/2026-10-10.md "体检" --to future           # 迁到未来记录（源行标 [>]）
```

- `mark` 默认 `--mark done`；`--mark` 可取 `task`（`- [ ]`）/ `done`（`- [x]`）/ `cancelled`（`- [-]`）。
  以条目正文定位，与界面同一套模糊匹配：同一段正文出现多条时会拒绝（可加 `--line N` 指明行号）。**「删除」在 CLI 里也是「划去」**：原文留在文件里。
- `move` 把一条搬去远处的日志：`--to tomorrow`（推迟到明天，源行标 `[<]`）/
  `next-month`（下个月的月度记录，`[>]`）/ `future`（未来记录，`[>]`）。
  与界面同一套语义：目标按类型落到对应小节、重复不复制，源文件只改标记不删行；
  已迁移（`[>]`）的条目会被拒绝，先 `mark --mark task` 取消迁移再搬。
  这个命令给「月初做迁移，把上月没做的事搬进新月记录」的 agent 流程用。
- **并发安全**：多个 CLI 进程、甚至与应用同时写同一份笔记都不会互相覆写——每个写操作在队列里串行执行，且同一文件的读改写由跨进程文件锁保护（不同文件互不等待）。
- **队列有界**：等待中的写操作达到上限（`BUJO_WRITE_QUEUE_MAX`，默认 32）时，新操作**不排队、立即失败**，不会无限囤积。
- 退出码：`0` 成功；`2` 用法/操作失败（文件不存在、找不到条目等）；`3` 队列满（JSON 里 `error.code = EWRITE_QUEUE_FULL`）；`4` 等待文件锁超时（`EWRITE_LOCK_BUSY`）。加 `--json` 后失败也会输出结构化错误。

## 在窗口里完成 / 划去条目

鼠标移到任意条目上（或 Tab 聚焦它）就能看到小按钮，点一下就写回文件、整篇重新载入：

| 按钮 | 作用 | 文件里变成什么 |
| --- | --- | --- |
| `完成` | 标记待办已完成（带删除线的 ✕） | `- [x] 文字` |
| `取消完成` | 已完成的改回待办 | `- [ ] 文字` |
| `划去` | 划掉一条（原文保留，不再跟进） | `- [-] 文字` |
| `恢复` | 已划去的恢复为待办 | `- [ ] 文字` |
| `»`（迁移） | 弹出小菜单，把这一条搬到**明天 / 下个月 / 未来记录**的日志里（详见下节） | 源行变 `‹` 或 `›` |

- **「划去」不是删除**：改动只发生在那一行的标记上，原文字、缩进、行序全部保留，
  所以划掉的条目仍然在文件里（也会被统计到「划去」里），随时可以「恢复」。
- 待办 / 优先 / 计划 / 迁移这类可以「完成」；笔记与事件只能「划去」；已经划去的只给「恢复」。
- 待办、笔记、事件与已计划（`[<]`）的条目都能「迁移」；**已迁移（`[>]`）、已划去、已完成的没有迁移按钮**，
  服务端也会拒绝（不能为了迁一次而把另一头的副本多搬一份）。
- **取消迁移/推迟**：已迁移（`[>]`）与已推迟（`[<]`）的条目带一个「取消迁移 / 取消推迟」按钮，
  把这一行恢复为普通待办；已写进目标日志的副本原地不动、按它自己处理。
  取消之后想再迁，或者直接去目标日志迁那个副本，都等于**重新迁移旧项目**：重新标 `[>]`，
  目标里已有的那份不会重复加（去重）。
- 操作后右下角会闪一句结果（「已标记为已划去（原文保留）」）。

### 迁移与推迟（Bullet Journal 的 [>] / [<]）

条目上的 `»` 按钮弹出三个目的地（与日记目录的「年 → 月」结构对应）：

| 目的地 | 写进哪个文件 | 这一行在**源文件**里变成什么 |
| --- | --- | --- |
| 推迟到明天 | 明天的每日日记（`2026-10-15.md`，不存在就按模板新建） | `- [<] 原文`（计划） |
| 迁移到下个月 | 下个月的「月度记录」 | `- [>] 原文`（迁移） |
| 迁移到未来记录 | 某年的「未来记录」 | `- [>] 原文` |

- 目标文件写到对应小节（「## 任务 / ## 事件 / ## 笔记」，按原来的类型落位），
  且**去重**：同一句正文已在目标文件里时不再复制一遍（提示「没有重复加」）。
- 源文件里只改那一行的标记、不改不删——原条目仍在原地。
  **已迁移（`[>]`）的条目不能再从原地迁一次**：先「取消迁移」（恢复为待办）再搬，
  或者直接迁移目标日志里的那份副本——两者都等于重新迁移旧项目，目标不会重复加。
- 跨月/跨年自动归位：任何日期推到「明天」，需要时下一代年（12-31 → 1-01）与月文件夹都会建好。
- CLI 同步支持：`npm run cli -- move 文件 "正文" --to tomorrow|next-month|future`（加 `--json` 可读结构化结果）。
- 写口是精确的：界面把**行号 + 正文**一起交给主进程，主进程重新读文件核对——
  你在外部编辑器里改过、行号偏了也能按内容找回来；找不到、或者好几条一模一样时**拒绝写入**并提示重新载入，绝不改错行。
- 段落、标题不会被当成条目（没有按钮），也不会被改动。

### 界面主题（浅色/深色，可选文件放在 css 文件夹里）

主界面工具栏右侧有「主题」下拉，一键在浅色/深色之间切换，选择会记住（下次启动直接套上）：

- 样式按「布局基底 + 主题」两层组织：`src/renderer/styles/base.css` 是全部布局规则与颜色 token（变量）的定义，
  `dark.css` / `light.css` 只负责覆写这些 token——深色是与历史界面完全一致的默认值，浅色是纸面感的浅色版（含原生控件 `color-scheme: light`）。
- **加新主题不用改任何代码**：复制 `light.css` 改成自己的 token 值（例如 `warm-paper.css` 暖纸色），放进 `styles/` 文件夹，
  重启应用就会出现在下拉里（主进程扫描文件夹，中文名给内置的两个，其它按文件名展示）。
- 主题存放在设置里（用户目录的 settings.json，不进项目），坏值/删掉主题文件时自动回落到默认深色。
- 悬浮小窗、聊夭面板、设置弹窗与自检的复核页全都走同一套 token，切主题一次性生效。

### 设置与密钥

点 `⚙` 打开设置，选服务商预设（OpenAI / DeepSeek / Moonshot / 智谱 / OpenRouter / 本地 Ollama / 自定义）
再填 API Key。接口是 OpenAI 兼容的 `/chat/completions`，所以任何兼容服务填上地址和模型名都能用。

提示词分两部分：

- **系统提示词**（可在设置里改）只写角色、语气和回答风格，不用考虑输出格式。
- **格式约定**（应用自动追加）：三段式标签、改动指令写法、子弹符号清单，以及「先看参考笔记、同一件事不要重复记」的规则；
  在设置里展开就能看到原文，写进代码里随功能一起更新。
- 旧版本的默认提示词会在读取时自动升级成新文案（它描述的是旧行为）；你手动改过或清空的提示词一律不动。

密钥的安全边界：

- 密钥只存在**主进程**，用 Electron `safeStorage`（Windows DPAPI / macOS 钥匙串）加密后写在
  `app.getPath('userData')/settings.json`——不进项目目录、不进版本库，也不出现在界面、日志或截图里。
- 渲染层调 `settings:get` 只能拿到「是否已配置」和末四位提示；**明文绝不会下发到界面**。
- 系统不支持加密时会降级为明文存储，并在设置里如实提醒。
- 聊天请求也全部在主进程发出，界面只接收流式文本。
- 「写入笔记」有白名单：只能写你本次打开过的文件，或日记目录里的文件，其它路径一律拒绝。

## 主窗口能做什么

- **左侧日记栏**：按 `年 → 月` 分组织出日记目录（默认 `journals/`）里的所有 Markdown 文件；
  每个年份组固定带一行「未来记录」（年度记录），每个月组固定带一行「月度记录」+ 该月的每日记录，新的在前；
  **单击选中、双击打开**，回车也能打开；当前打开的一篇会高亮；
  年度/月度记录还没建时是一行「＋ 双击新建」，双击就会按模板建出来并打开（不存在才建，绝不覆盖）。
- **可收起**：点标题栏的 `‹` / `›` 把日记栏收成一条 42px 的窄条，收起后只留「展开」按钮（列表、目录路径、刷新按钮都隐藏），状态会记住。
- **打开笔记**：顶部按钮、`Ctrl/Cmd + O`、拖拽 `.md` 到窗口，或通过启动参数传入路径。
- **预览 / 原文切换**：预览用 Markdown 渲染，子弹条目按类型着色；原文显示文件原始内容。工具栏还能一键切换浅色/深色主题（选择会记住，详见上文「界面主题」）。
- **重新载入**：在外部编辑器改完文件后一键刷新。
- **条目上的按钮**：鼠标移上去就能「完成 / 取消完成 / 划去 / 恢复」以及「迁移/推迟（`»`）」一条条目，详见上文两节。
- **统计条**：待办 / 完成 / 划去 / 优先 / 事件 / 迁移 / 笔记数量与完成进度。
- 笔记中的 http(s) 链接交给系统浏览器打开，不会在应用内跳转。

会改写笔记的只有两件事：你自己的「完成 / 划去 / 恢复」与 AI 的「写入笔记」，
两者都只能动白名单内的文件，且都只改单行的标记/文字，没有任何路径会让一整行默默消失。

## 子弹笔记语法

一行是不是「子弹」，以及属于哪种子弹，由行首符号决定：

| 写法 | 显示符号 | 含义 |
| --- | --- | --- |
| `- [ ] 任务` / `• 任务` | `•` | 待办任务 |
| `- [x] 任务` | `✕` | 已完成（带删除线） |
| `- [-] 任务` | `✗` | 划去（原文保留，带删除线） |
| `- [>] 任务` | `›` | 迁移到未来日志 |
| `- [<] 任务` | `‹` | 计划 / 安排到某天 |
| `- [!] 任务` | `★` | 优先任务 |
| `- 一句话` | `–` | 普通笔记 |
| `o 事件` | `o` | 事件（只记录，不行动） |

其他规则：

- 用两个空格或制表符缩进即可形成子条目层级。
- 代码围栏（` ``` `）里的内容和普通段落不会被当成子弹。
- 复选框之外的 Markdown（标题、表格、引用、代码块）仍按标准 Markdown 渲染。

## 项目结构

```
src/
  main/
    main.js           主进程：创建主窗口、注册 IPC、菜单/链接安全策略
    file-service.js   只读的 Markdown 文件读取与校验
    journal-service.js 日记目录扫描 + 按模板新建当天的日志
    note-service.js   读写笔记：追加写入 + 整合写入（改已有条目、跳过重复）+ 单行改标记（setBulletMark），写操作都走共享队列与跨进程文件锁
    theme-service.js  界面主题扫描：styles/ 文件夹里的每个 .css（除 base.css 布局基底）都是一个可选主题
    write-queue.js    有界串行写入队列 + 跨进程文件锁（应用与 CLI 共用；队列满立即拒绝）
    settings-service.js 设置与 API Key（safeStorage 加密，密钥不外泄）
    chat-service.js   OpenAI 兼容的流式聊天（SSE 解析、超时、取消、错误翻译）
  preload/
    preload.js        contextBridge 白名单，渲染层唯一的文件访问入口
  renderer/
    index.html        主窗口结构
    styles/           界面样式：base.css（布局基底 + 全部颜色 token）+ dark.css / light.css（主题文件）
    renderer.js       打开/拖拽文件、解析结果渲染、条目上的完成/划去/恢复按钮、结果提示、视图切换、日记栏与折叠、主题切换
    chat.js           聊天面板、笔记草稿卡片（新增+改动）、参考笔记选择、设置弹窗、写入与预览、流式渲染
  shared/
    bullet-parser.js  子弹笔记解析器：类型判定 + 每条带上源文件行号（浏览器与 Node 共用，含单元测试）

### 日记目录结构（年 → 月 → 每日）

```text
journals/
  .journal-structure-v2        旧结构一次性迁移的标记（迁移只跑一次）
  2026/                        年文件夹
    未来记录.md                 年度（未来）记录，一年一篇
    2026-10/                   月文件夹
      月度记录.md               月度记录，一月一篇
      2026-10-13.md            每日记录，一天一篇
```

- 启动时会一次性把旧版平铺结构（`journals/2026-10-07.md`、`journals/2026-10.md`）
  自动迁进对应 年/月 文件夹（平铺月记改名 `月度记录.md`），迁移完留标记不再重复；
  目标已存在时不动原来的文件。
- 「未来记录」「月度记录」在侧边栏点开对应节点时才会按模板创建；
  每日记录在记入日记时自动建。

日记目录可用环境变量 `BUJO_JOURNALS` 指定（默认是项目根下的 `journals/`）：

```bash
BUJO_JOURNALS=D:/我的日记 npm start
```

安全模型：渲染层 `contextIsolation: true` + `nodeIntegration: false`，只有
`preload.js` 暴露的 `window.bujo`（读文件、列目录、选文件、打开外链）可用，并有 CSP 限制。
日记栏只能看到日记目录里的一层 `.md` 文件，读不了目录以外的东西。

自检会启动一个隐藏窗口完成全部验证，验证不通过时退出码非 0，成功时输出截图：
`screenshots/main-window.png`（展开）、`sidebar-collapsed.png`（收起）、`chat-panel.png`（聊天面板），
以及 `screenshots/chat-panel.html`——用真实 DOM + 真实样式表拼出的复核页，打开就能看清气泡与笔记草稿卡片（新增条目、改动清单、去重预览）。

自检覆盖的内容：解析与渲染、日记栏双击切换、折叠（含计算样式与像素宽度）、
以及**聊天全链路**——它会起一个本地假模型服务（不联网、不用真密钥），把设置指向它，跑完
「发消息（带上已有笔记作为上下文）→ 流式接收 → 气泡里只有对话、卡片分别列出新增与改动 →
写入笔记 → 文件里只有该写的两部分」：自检会断言改动的确是**已有那一行**被改了、重复的条目**只留一条**，
对话内容与标签都不允许出现在笔记文件里；同时核对真正发出去的请求体
（系统提示词含三段式协议与整合规则，笔记正文只在用户消息里），再补一轮「模型不按协议回答」验证兜底按钮，
并数一遍右侧面板的像素确认真的画出了内容，最后把原来的设置文件恢复回去。

聊天面板的**等待态**也被覆盖：发消息后 AI 回复前会先出现「正在思考…」的占位气泡与草稿卡占位（「等待 AI 回复…」），
收到流式增量后立即被真实内容替换，不会有先跳出来的空卡片。

手工操作那一条也被完整跑过一遍（在临时文件上，不碰你的日记）：真的去点界面上的按钮，
按「待办→完成 / 笔记→划去 / 待办→划去→恢复」走一遍，断言文件里那三行分别变成了 `- [x]`、`- [-]`、`- [ ]`，
且**行数一个不少**（划去不是删除）；同时检查按钮真的排了版、在窗口里看得见，以及提示条确实弹了出来。
这一条里还带上了**迁移与推迟的端到端**：在界面上把任务推到明天（源行变 `[<]`、明天的日记出现这一条且落到对应小节）、
把笔记迁到下个月的月度记录（源行变 `[>]`、月度记录里出现原文）、再确认两个目标文件里都没有重复行。
（顺带一个细节：自检改用独立的临时 userData，不动正在运行的正式应用与它的日记。）

悬浮小窗的切换闭环也在自检里：用真实 IPC 开悬浮窗（主窗口隐藏、置顶），断言精简页形态
（悬浮条、工具栏/侧栏/图例被隐藏、当天日记自动载入或显示空态提示、聊天面板展开、「回主窗口」按钮），
再关闭并断言主窗口恢复。见下节。

## 悬浮小窗

工具栏的「悬浮小窗」按钮把主窗口切到一个**无边框**的紧凑置顶小窗（360×560，可调，不进任务栏，无系统标题栏，**不可最大化**）：

- 页面顶部是一条可拖拽的**悬浮条**：左「⌂」回主窗口、中间「• 今日要点」标题、
  右上角「−」按钮 —— 点它把整个窗**收成一条窄条**（同宽高度不变，只收到悬浮条一条），再点「＋」展开回完整悬浮窗；
  切换通过 `floating:set-collapsed` IPC 调整窗口尺寸，页面状态全程不丢。
- **记住位置**：拖动/改尺寸后自动落盘（防抖），关窗兜底冲刷；下次切回悬浮窗、
  重启应用、或从托盘打开时，悬浮窗回到上次的位置与大小。
- 正文区：自动载入今天的日记，条目上的完成/划去/恢复按钮照常可用；日记不存在时提示回主窗口创建。
  正文之上、聊天贴底：聊天面板占满悬浮条以下全部剩余高度，输入行永远紧贴窗口底边
  （消息区收起时输入行也推到底边），窗口里不留大片背景空区。
  **消息区收起时正文撑满**：整个余下高度都是正文（过长自己滚动），聊天只剩底部一行输入，中间没有半屏空区。
- 回复区右上角有折叠/展开钮：展开时贴回复区右上角（向下收），收起后贴输入行上方（向上开）；
  向 AI 发送消息时回复区自动展开；AI 正在生成时收/展锁定，生成完才能操作。
- **AI 聊天仅在 AI 有最新回复时弹出**：平时消息区收起，底部只剩一行压缩的输入区
  （不可关闭）；AI 首个流式增量到达时消息区自动弹出并滚到最新；点右上角钮可收起，
  再有新回复时未读点亮起；折叠态收到回复会先自动展开窗口再弹消息。
- 点「⌂」或关掉小窗，主窗口恢复；主窗口只是隐藏而非销毁，切回来时聊天历史、
  未发送的内容、正在生成的请求都还在。
- 主窗口 ⇄ 悬浮窗的切换由 `window:toggle-floating` IPC 完成，
  两个窗口加载同一个页面（悬浮窗 URL 带 `?floating=1`，渲染层据此切换精简布局）。

## 关闭 → 系统托盘

关掉主窗口不是退出：窗口被收进**系统托盘**（右下角，深蓝底圆点图标），应用继续在后台驻留：

- 首次收进托盘时弹出气泡提醒（其它平台静默处理）；写日记、AI 聊天请求在后台照常进行。
- **左键**托盘图标：重新唤出主窗口（窗口已销毁时会新建）。
- **右键菜单**：打开主窗口 / 打开悬浮小窗 / 退出。
- **退出只在托盘菜单里**：置位退出标志后所有窗口真正关闭、托盘销毁；
  窗口全关时应用不再退出（托盘在就住在托盘里）。

自检也覆盖了托盘链路：图标产物（16×16 非空位图）、真实触发 close 断言「藏起而非销毁」、
退出置位路径；托盘图标的真人点按交互需人工核对。
