# 子弹笔记 · Bullet Journal Desktop

基于 Electron 的子弹笔记（Bullet Journal）桌面应用。

当前进度：**主窗口 + 左侧日记栏 + 读取并显示 .md 笔记 + AI 聊天读写笔记（读已有笔记作上下文、可改已有条目、写入时整合去重）**。
直接在窗口里手写/编辑条目是下一步，数据格式已经按子弹笔记语法打好基础（见下文）。

## 运行

```bash
npm install
npm start          # 启动应用
npm test           # 单元测试（解析器 + 文件读取 + 日记目录扫描）

# 端到端自检：preload → IPC → 解析 → 渲染 → 日记栏双击切换 → 折叠，并输出截图
npm run smoke
npm run smoke -- journals/2026-10-07.md   # 也可以指定自检打开的文件
```

也可以直接把 `.md` 文件拖进窗口，或用 `npm start -- journals/2026-10-07.md` 启动时直接打开。

## AI 聊天（与笔记打通）

右侧面板可以和模型聊天，**回答分成三段**：对话、要新增的条目、对已有条目的改动——
只有后两段会动到笔记：

- 点工具栏的「AI 聊天」（或 `Ctrl/Cmd + J`）展开右侧面板，聊天内容流式显示。
- 模型按协议用 `<chat>…</chat>`、`<journal>…</journal>`、`<note-edit>…</note-edit>` 分段
  （协议由应用自动追加到系统提示词里，也可以用小标题 `【日记】`、`日记块：`、`## 日记`、`笔记改动：` 代替标签）。
- **气泡里只显示对话**：解释、建议、追问都留在这里；**笔记草稿**单独成一张卡片，
  卡片下方才是「写入笔记」按钮——只有卡片里的内容会落盘，聊天里的寒暄不会被当成笔记条目。
- **参考笔记**（底部的「参考」下拉）：选「当前笔记」或「今天的日记」后，应用会把那一篇的现有内容
  作为 `<note file="…">…</note>` 附在你的提问后面发给模型（太长时首尾保留、中间省略，默认最多 2400 字）。
  这样 AI 能看到哪些事已经记过；选「不附带」就是纯粹聊天。
- **改动已有条目**：卡片上的「改动」清单来自 `<note-edit>`，一行一条——
  `改：原文 => 新写法`、`完成：原文`、`删：原文`。应用按归一化后的文本在本篇笔记里模糊匹配（完全相同 → 内容近似），
  匹配不到就明确报「没找到」，宁可不改也不拿相近的行乱改。
- **整合而非重复**：写入前会跳过与已有条目重复的新增条目（完全相同或高度相似），
  同一件事只是状态变了（待办 → 已完成等）就**就地改状态**，不再新增一条；
  一批新增里自己重复的也只留一条。卡片上会提前显示「对照当前笔记：新增 N 条 · 改动 M 处 · 跳过重复 K 条」。
- 写入时把内容改写成子弹笔记条目：`- [ ]` 之类的任务原样保留，`*` / `1.` / `>` 等写法统一成 `-`,
  代码块和标题原样保留；有新增条目时前面加一行 `**AI 记录 · 14:32**`（只有改动时不加时间戳），
  卡片上的「带提问」勾选后还会附上你的问题。写入结果会写明新增/并入/改动/跳过重复各几条。
- 按「记入」选择的目标，写进**当前打开的笔记**或**今天的日记**
  （今天的日志不存在时会按模板新建 `journals/YYYY-MM-DD.md`）。
- 两段都为空时（AI 认为这轮没什么值得记的）不会写；模型完全不按协议回答时，
  卡片会说明白，并给一个「写入全文要点」的兜底按钮，不会默默把整段对话当笔记写进去。
- 生成过程中可以「停止」；没配密钥时会直接提示去设置。
- 真正的落盘在主进程完成：它重新读一遍文件、按同一套规则再算一次，
  渲染层只负责预览与展示（两边共用 [note-edit.js](src/shared/note-edit.js)，界面上的数字与文件里的结果一致）。

### 设置与密钥

点 `⚙` 打开设置，选服务商预设（OpenAI / DeepSeek / Moonshot / 智谱 / OpenRouter / 本地 Ollama / 自定义）
再填 API Key。接口是 OpenAI 兼容的 `/chat/completions`，所以任何兼容服务填上地址和模型名都能用。

提示词分两部分：

- **系统提示词**（可在设置里改）只写角色、语气和回答风格，不用考虑输出格式。
- **格式约定**（应用自动追加）：三段式标签、改动指令写法、子弹符号清单，以及「先看参考笔记、同一件事不要重复记」的规则；
  在设置里展开就能看到原文，写进代码里随功能一起更新。
- 旧版本的默认提示词会在读取时自动升级成新文案（它描述的是旧行为）；你手动改过或清空的提示词一律不动。

密钥的安全边界：

- 密钥只存在**主进程**，用 Electron `safeStorage`（Windows DPAPI / macOS 钥匙串）加密后写在
  `app.getPath('userData')/settings.json`——不进项目目录、不进版本库，也不出现在界面、日志或截图里。
- 渲染层调 `settings:get` 只能拿到「是否已配置」和末四位提示；**明文绝不会下发到界面**。
- 系统不支持加密时会降级为明文存储，并在设置里如实提醒。
- 聊天请求也全部在主进程发出，界面只接收流式文本。
- 「写入笔记」有白名单：只能写你本次打开过的文件，或日记目录里的文件，其它路径一律拒绝。

## 主窗口能做什么

- **左侧日记栏**：列出日记目录（默认 `journals/`）里所有 Markdown 文件，最新在前；**单击选中、双击打开**，回车也能打开；当前打开的一篇会高亮。
- **可收起**：点标题栏的 `‹` / `›` 把日记栏收成一条 42px 的窄条，收起后只留「展开」按钮（列表、目录路径、刷新按钮都隐藏），状态会记住。
- **打开笔记**：顶部按钮、`Ctrl/Cmd + O`、拖拽 `.md` 到窗口，或通过启动参数传入路径。
- **预览 / 原文切换**：预览用 Markdown 渲染，子弹条目按类型着色；原文显示文件原始内容。
- **重新载入**：在外部编辑器改完文件后一键刷新。
- **统计条**：待办 / 完成 / 优先 / 事件 / 迁移 / 笔记数量与完成进度。
- 笔记中的 http(s) 链接交给系统浏览器打开，不会在应用内跳转。

除了 AI 的「写入笔记」（只会追加到白名单内的文件），其余操作都只读，不会改写你的笔记。

## 子弹笔记语法

一行是不是「子弹」，以及属于哪种子弹，由行首符号决定：

| 写法 | 显示符号 | 含义 |
| --- | --- | --- |
| `- [ ] 任务` / `• 任务` | `•` | 待办任务 |
| `- [x] 任务` | `✕` | 已完成（带删除线） |
| `- [>] 任务` | `›` | 迁移到未来日志 |
| `- [<] 任务` | `‹` | 计划 / 安排到某天 |
| `- [!] 任务` | `★` | 优先任务 |
| `- 一句话` | `–` | 普通笔记 |
| `o 事件` | `o` | 事件（只记录，不行动） |

其他规则：

- 用两个空格或制表符缩进即可形成子条目层级。
- 代码围栏（` ``` `）里的内容和普通段落不会被当成子弹。
- 复选框之外的 Markdown（标题、表格、引用、代码块）仍按标准 Markdown 渲染。

## 项目结构

```
src/
  main/
    main.js           主进程：创建主窗口、注册 IPC、菜单/链接安全策略
    file-service.js   只读的 Markdown 文件读取与校验
    journal-service.js 日记目录扫描 + 按模板新建当天的日志
    note-service.js   读写笔记：追加写入（保证空行与结尾换行）+ 整合写入（改已有条目、跳过重复）
    settings-service.js 设置与 API Key（safeStorage 加密，密钥不外泄）
    chat-service.js   OpenAI 兼容的流式聊天（SSE 解析、超时、取消、错误翻译）
  preload/
    preload.js        contextBridge 白名单，渲染层唯一的文件访问入口
  renderer/
    index.html        主窗口结构
    styles.css        深色主题与子弹符号配色
    renderer.js       打开/拖拽文件、解析结果渲染、视图切换、日记栏与折叠
    chat.js           聊天面板、笔记草稿卡片（新增+改动）、参考笔记选择、设置弹窗、写入与预览、流式渲染
  shared/
    bullet-parser.js  子弹笔记解析器（浏览器与 Node 共用，含单元测试）
    ai-reply.js       把回答拆成「对话 / 新增条目 / 笔记改动」+ 三段式协议提示词（含单元测试）
    note-edit.js      改动指令的解析与整合：模糊匹配已有条目、跳过重复、就地改状态（含单元测试）
    note-context.js   把已有笔记拼成 <note> 上下文块（首尾保留、中间省略，含单元测试）
    chat-to-note.js   日记块 → 子弹笔记条目（时间戳/提问与条目分开，方便整合）
    journal-date.js   日期/星期/时间标签（主进程与渲染层共用）
samples/
  Bullet-Journal.md   示例笔记（用于演示各种子弹符号）
journals/             日记目录：一天一个 .md 文件，命名约定见 journals/README.md
test/                  node:test 单元测试
```

日记目录可用环境变量 `BUJO_JOURNALS` 指定（默认是项目根下的 `journals/`）：

```bash
BUJO_JOURNALS=D:/我的日记 npm start
```

安全模型：渲染层 `contextIsolation: true` + `nodeIntegration: false`，只有
`preload.js` 暴露的 `window.bujo`（读文件、列目录、选文件、打开外链）可用，并有 CSP 限制。
日记栏只能看到日记目录里的一层 `.md` 文件，读不了目录以外的东西。

自检会启动一个隐藏窗口完成全部验证，验证不通过时退出码非 0，成功时输出截图：
`screenshots/main-window.png`（展开）、`sidebar-collapsed.png`（收起）、`chat-panel.png`（聊天面板），
以及 `screenshots/chat-panel.html`——用真实 DOM + 真实样式表拼出的复核页，打开就能看清气泡与笔记草稿卡片（新增条目、改动清单、去重预览）。

自检覆盖的内容：解析与渲染、日记栏双击切换、折叠（含计算样式与像素宽度）、
以及**聊天全链路**——它会起一个本地假模型服务（不联网、不用真密钥），把设置指向它，跑完
「发消息（带上已有笔记作为上下文）→ 流式接收 → 气泡里只有对话、卡片分别列出新增与改动 →
写入笔记 → 文件里只有该写的两部分」：自检会断言改动的确是**已有那一行**被改了、重复的条目**只留一条**，
对话内容与标签都不允许出现在笔记文件里；同时核对真正发出去的请求体
（系统提示词含三段式协议与整合规则，笔记正文只在用户消息里），再补一轮「模型不按协议回答」验证兜底按钮，
并数一遍右侧面板的像素确认真的画出了内容，最后把原来的设置文件恢复回去。
